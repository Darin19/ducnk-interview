A. Giao diện Test Data Management / Admin UI

      Nhập thông tin nhân viên giả lập.

     con=engine,
     if_exists="append",
     index=False,
     method="multi",
     chunksize=500
 )

2. Luồng chuẩn nên áp dụng cho HRAI

Không nên insert tất cả vào một bảng. Nên tách thành các lớp dữ liệu.


 Nguồ     n testcase
 Excel / UI / Python Generator / API
                 ↓
 1. Testcase Ingestion
 Nhận file hoặc request
                 ↓
 2. Schema Validation
 Kiể  m tra cột bắ                           t buộc, kiể                         u dữ liệu, format
                 ↓
 3. Business Validation
 Kiể  m tra tổ                 hợp feature hợp lệ
                 ↓
 4. Staging Database
 Lưu dữ liệu tạm thời
                 ↓
 5. Data Quality Check
 Trùng testcase, thiế                                                  u feature, giá trị bấ                                                     t hợp lý
                 ↓
 6. Dataset Builder
 Tạo hồ            sơ nhân viên + feature + expected result
                 ↓
 7. Publish Dataset Version
 Ví dụ HRAI_GOLDEN_V3
                 ↓
 8. Trigger AI
 Airflow/API gử                                 i từng testcase cho AI
                 ↓
 9. AI tra                   ̉ kế     t qua        ̉
 Lưu actual result vào DB
                 ↓
 10. Evaluation Engine
 So sánh expected với actual
                 ↓
 11. QA Review
 PASS / PARTIAL PASS / FAIL + comment
                 ↓
 12. Feedback Dataset
 Tạo dataset mới cho prompt tuning, fine-tuning hoặc regression

4. Kiểm tra expected và actual


 SQL
 SELECT
     tc.test_case_code,
     ex.expected_risk_type,
     ac.actual_risk_type,
     ex.expected_risk_level,
     ac.actual_risk_level,
     ac.actual_score,
     CASE
         WHEN ex.expected_risk_type = ac.actual_risk_type
          AND ex.expected_risk_level = ac.actual_risk_level
         THEN 'PASS'
         ELSE 'FAIL'
     END AS test_result
 FROM qa_test_case tc
 JOIN qa_expected_ai_result ex
     ON ex.test_case_id = tc.test_case_id
 JOIN qa_actual_ai_result ac
     ON ac.test_case_id = tc.test_case_id;

5. Phân tích lỗi

Ví dụ tìm các trường hợp AI phân loại sai dù có cùng feature:


 SQL
 SELECT
     f.feature_code,
     f.feature_value_text,
     COUNT(*) AS total_cases,
     SUM(
         CASE
             WHEN ex.expected_risk_type <> ac.actual_risk_type
             THEN 1
             ELSE 0
         END
     ) AS failed_cases
 FROM qa_test_feature_input f
 JOIN qa_expected_ai_result ex
     ON ex.test_case_id = f.test_case_id
 JOIN qa_actual_ai_result ac
     ON ac.test_case_id = f.test_case_id
 GROUP BY
     f.feature_code,
     f.feature_value_text;

 SQL
 DELETE FROM qa_actual_ai_result

 DELETE FROM qa_test_feature_input
 WHERE test_case_id IN (
     SELECT test_case_id
     FROM qa_test_case
     WHERE dataset_version = :dataset_version

Airﬂow

Airﬂow chỉ cần thiết khi muốn:

      Chạy hàng nghìn nhân viên.

      Chạy nhiều model hoặc prompt version.

      Tự động chạy regression mỗi ngày.
      Điều phối load data → feature → AI → evaluation.

      Retry khi một bước lỗi.

Airﬂow DAG mô tả các task, dependency và thứ tự thực hiện của workﬂow, nên phù hợp với pipeline
kiểm thử batch về sau.      Apache Airﬂow+1
